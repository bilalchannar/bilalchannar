## 🧠 Engineering Mindset & Architecture Principles

<details>
<summary><b>1. Modular Architecture & Clean Separation of Concerns (SoC)</b></summary>
<br/>
<p>I design applications around clear boundaries. In mobile applications, I isolate business logic from widget trees using clean MVVM/repository patterns. In web backends, routes, controllers, services, and database layers remain decoupled to simplify testing and refactoring.</p>
</details>

<details>
<summary><b>2. Scalable Containerization & Infrastructure Parity</b></summary>
<br/>
<p>To eliminate environment mismatches, I containerize full-stack backend services using Docker. Packaging micro-services (Flask, Svelte, MongoDB) into container networks guarantees predictable deployment across development and production environments.</p>
</details>

<details>
<summary><b>3. Security-First Systems Design</b></summary>
<br/>
<p>Security is baked in from day one. I implement stateless authentication using signed JWT tokens, hash credentials with bcrypt, restrict API misuse using express rate-limiters, store tokens securely on mobile hardware, and validate user input on all endpoints.</p>
</details>

<details>
<summary><b>4. Data-Driven Analytics & Empirical Metrics</b></summary>
<br/>
<p>Whether analyzing real-time visitor geolocations via Chart.js or evaluating Machine Learning models ($R^2$ score, Root Mean Squared Error, feature importance plots), I rely on empirical metrics to assess performance and drive system improvements.</p>
</details>

<details>
<summary><b>5. Maintainable & Self-Documenting Engineering</b></summary>
<br/>
<p>Writing maintainable code is as crucial as functional implementation. I prioritize self-documenting method signatures, explicit variable naming, clean Git commit histories, and comprehensive README documentation.</p>
</details>

> **Automating technical talent acquisition by extracting unstructured PDF resume data, converting text to TF-IDF vectors, and ranking candidate suitability via Cosine Similarity.**

<p align="center">
  <img src="https://img.shields.io/badge/Svelte-FF3E00?style=for-the-badge&logo=svelte&logoColor=white" />
  <img src="https://img.shields.io/badge/Python_Flask-000000?style=for-the-badge&logo=flask&logoColor=white" />

  <img src="https://img.shields.io/badge/Docker-2496ED?style=for-the-badge&logo=docker&logoColor=white" />
</p>

#### 📌 Problem & Motivation
Technical recruiters face severe bottlenecks manually reviewing hundreds of PDF candidate resumes for single job postings. Standard keyword search tools fail to evaluate semantic relevance or technical keyword context accurately.

#### 🏗️ Architecture & System Flow
```
+------------------+     +-------------------+     +----------------------+
| Candidate PDF    | --> | PyPDF2 / PDFPlumber| --> | Text Preprocessing   |
| Resume Upload    |     | Text Extractor    |     | (Stopwords, Clean)   |
+------------------+     +-------------------+     +----------------------+
                                                               |
                                                               v
+------------------+     +-------------------+     +----------------------+
| Candidate Rank   | <-- | Cosine Similarity | <-- | TF-IDF Vectorization |
| Output Dashboard |     | Match Score (0-1) |     | (Scikit-Learn)       |
+------------------+     +-------------------+     +----------------------+
```

#### ⚡ Key Engineering Features
- **PDF Text Extraction Pipeline:** Automated parsing of raw PDF resume text for keyword normalization.
- **NLP Match Ranking:** Built a vector scoring model using `scikit-learn` TF-IDF Vectorizer and Cosine Similarity.
- **Full-Stack REST Architecture:** Lightweight Svelte frontend communicating with a Flask API storing candidate profiles in MongoDB.
- **Security & Docker Containerization:** Secured with JWT authentication and packaged in Docker containers for reproducible multi-environment deployment.

#### 🔑 Key Challenges Solved
- **Parsing Variable PDF Layouts:** Handled unstructured multi-column PDF layouts by normalizing whitespace and tokenizing text before vector transformation.
- **Scalable Ranking Computation:** Optimized Cosine Similarity matrix calculations to return candidate scores in under 500ms.

#### 📌 Problem & Motivation
Generic URL shorteners rarely provide granular analytics regarding visitor geolocations, device breakdowns, or password-protected access controls for sensitive destination links.

#### 🏗️ Architecture & System Flow
```
[ Client Request ] --> [ Express Rate Limiter ] --> [ JWT Auth Middleware ]
                                                            |
                                                            v
[ Chart.js Analytics ] <-- [ MongoDB Analytics Doc ] <-- [ Geolocation Lookup ]
                                                            |
                                                            v
                                                   [ Destination Redirect ]
```

#### ⚡ Key Engineering Features
- **Visitor Telemetry Engine:** Real-time collection and visualization of click metrics, geographic origin, browser info, and device type using `Chart.js`.
- **Automated Expire Scheduler:** Integrated `Node-Cron` background jobs to query and purge expired links without impacting core redirect latencies.
- **Security Protections:** Implemented Express rate-limiting to prevent URL redirection abuse, password protection for private links, and signed JWT authentication.

#### 🔑 Key Challenges Solved
- **Abuse Prevention:** Mitigated brute-force link creation using sliding-window rate limiters per IP address.
- **Non-Blocking Analytics Logging:** Asynchronously recorded click metadata in MongoDB without delaying user HTTP redirect responses.

#### 🏗️ Architecture & System Flow
```
[ Zameen.com ] --> [ Selenium Web Scraper ] --> [ Data Preprocessing (Pandas/NumPy) ]
                                                                 |
                                                                 v
[ R² / RMSE Evaluation ] <-- [ Model Comparison ] <-- [ Feature Scaling & Encoding ]
```

- **Handling Scraping Rate Limits & Dynamic DOMs:** Designed robust explicit waits in Selenium to navigate pagination and avoid bot detection during scraping.
